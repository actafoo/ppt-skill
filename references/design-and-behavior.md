# 디자인·조작 기준

## 근거와 범위

참고 저장소: https://github.com/HooniKims/edutech_korea_fair
참고 사이트: https://edutech-korea-fair-seven.vercel.app/
관찰 근거는 README.md, DESIGN.md, src/Slides.tsx, src/styles.css, src/App.tsx와 src/data.ts이다. 원본 프로젝트는 PPT 그래픽과 사용자 제공 사진을 재배치하고 Paperlogy 및 Remotion으로 웹 발표를 구현했다. 특정 UI UX 디자인 스킬로 만들어졌다고 주장할 근거는 없다. 디자인·조작만 참고하고 행사 내용을 재사용하지 않는다.

## 시각 체계

- 글꼴: assets/fonts의 Paperlogy Regular 400, SemiBold 600, Bold 700, ExtraBold 800. @font-face로 로컬 제공하며 OFL-license.txt도 보존한다.
- 기본 색: 흰색 #FFFFFF, 짙은 남색 #001035, 초록 #00633E, 보조 보라 #7030A0. 본문 회색은 충분한 대조비를 확보한다. 남색 본문과 초록 강조를 우선하며 보라색은 범주 구분이 있을 때만 사용한다.
- 캔버스: 1920×1080에서 좌우 115~120px, 핵심 콘텐츠 안전 여백 80px 이상. 일반 제목 64~88px, 표지 제목 110~126px, 본문 34~44px, 보조 정보 26~30px를 출발점으로 삼고 실제 렌더에 맞춘다.
- 한 슬라이드 한 메시지. 설명이 넘치면 내용을 나누고 작은 글씨로 억지로 채우지 않는다.
- 원본 사진은 주 피사체를 보존한다. 세로 사진·단체 사진은 contain 중심, 장면 사진은 안전한 crop만 허용한다. 글자는 이미지에 합성하지 않는다.
- 공통 상단에 발표명·현재 주제, 하단에 장 번호·필요한 소속 표시. 개인 발표에 타 기관 로고를 자동 삽입하지 않는다.

## 내용별 화면

1. 표지: 왼쪽 큰 제목·짧은 부제, 오른쪽 해당 발표의 실제 사진/자산.
2. 설명: 큰 핵심 문장과 짧은 보조 설명. 중요한 단어만 초록.
3. 사진+문구: 왼쪽 큰 사진, 오른쪽 짧은 포인트 2~3개와 문장 하나.
4. 일정: 날짜를 크게, 요일은 작게, 활동 제목과 짧은 설명 아래에.
5. 단계 비교: 넓은 2~3열과 상단 강조선; 반복되는 둥근 카드와 과한 그림자를 피한다.
6. 사례: 문제 문구와 해결 아이디어를 왼쪽에, 시연/GIF/캡처를 오른쪽에 크게.
7. 전환·마무리: 남색/흑백 배경과 간결한 큰 제목. 초록은 강조에 제한한다.

## 동작

- F: 전체 화면. 방향키/Enter: 이전·다음. G: 목차. N: 발표 대본. Esc: 열린 창 또는 전체 화면 해제.
- 입력창·편집 영역에 포커스가 있으면 단축키가 입력을 방해하지 않는다. 키 반복으로 여러 장이 건너뛰지 않게 한다.
- 처음·마지막 장에서 순환하지 않는다. 위치와 슬라이드 제목을 항상 식별할 수 있게 한다.
- URL에서 슬라이드 위치를 지정하고 새로고침 시 복원한다. 발표 상태만 기기 로컬에 저장하며 학습자 기록 등 제품 데이터 저장과 혼동하지 않는다.
- 대본 창은 같은 출처에서 BroadcastChannel 등으로 현재 장을 동기화한다. 대본 창 음악은 음소거한다. 창 열기가 차단되면 명확한 다시 열기 버튼을 제공한다.
- 본문은 짧게 등장한 후 정지한다. 반복되는 GIF 때문에 글씨까지 반복 등장시키지 않는다. 미디어 종료만으로 다음 슬라이드로 넘어가지 않는다. 사용자가 오프닝 자동 연결을 요청한 때만 예외를 설정한다.
- 긴 타이포 시퀀스는 필요 시 Remotion Player로 구성한다. Player inputProps를 프레임마다 새로 만들지 않아 재생 시계 초기화를 피한다. 현재/다음 자산을 준비하고 GIF 전체를 동시에 재생하지 않는다.
- 음악은 사용자 입력 후 재생하고 음소거·정지 기능을 제공한다. reduced-motion에서는 정지 화면과 수동 조작으로 의미를 보존한다.

## 반응형 확인

행사 노트북/프로젝터에서 16:9를 비율 유지한다. 모바일에서는 발표 캔버스와 실제 조작 UI를 구분해 버튼 가독성과 터치 크기를 유지한다. 발표자 메모는 확대/스크롤 가능하게 한다. 브라우저가 없으면 확인 범위를 투명하게 보고한다.
